### 2.3 用户行为分析（基于点击轨迹观察）

1. **任务路径线性可走通**：从「创意输入 → 生成」的核心漏斗无认知断点，生成按钮的锁定/解锁状态正确引导操作顺序（前置未满足时禁用 + 锁图标提示）。
2. **视觉反馈及时性**：生成按钮点击后立即进入 loading 态（spinner + 文案），符合「点击后 100ms 内必须有反馈」标准；但分钟级长任务仅有 spinner，无分段进度/预计剩余时间，是最大等待焦虑点。
3. **节点即入口的心智成立**：点击节点打开详情面板、模态框保存后画布标题即时同步，双向数据一致性验证通过，用户无需手动刷新。
4. **画布自由度高但未失控**：缩放（zoom in/out）、拖拽、fit view 均可用；`maxZoom=1.5` + `fitView maxZoom=1` 限制了过度放大导致的迷失。
5. **禁用逻辑防错有效**：流程菜单在数据未就绪时禁用，从机制上杜绝了「跳步操作」类错误——本轮 0 错误率部分得益于此。

## 三、问题发现与修复记录

| 编号 | 严重度 | 问题 | 根因 | 处置 |
|---|---|---|---|---|
| F1 | **P0 阻断** | 剧本生成后 8 节点渲染但 7 条连接边全部缺失（SVG edges 容器为空） | React Flow v11 依赖 ResizeObserver 完成节点/handle 测量后才渲染边；在 rAF 被节流的环境（后台标签页/自动化浏览器）测量永不完成 | ✅ 已修复：`getLayoutedElements` 预置 `width/height` + 新增 `NodeInternalsUpdater` 组件主动调用 `updateNodeDimensions` 同步测量，节点数变化后自动 fitView。修复后边渲染回归验证通过 |
| F2 | **P1 严重** | 剧本生成请求后端长时间无响应（观测 >4.5min），前端无超时，永久 loading | `generateScript` 无超时保护 | ✅ 已修复：`fetchWithTimeout` 封装，300s 超时 + 友好中文错误提示 |
| F3 | P2 体验 | 画布背景残留深色块（#2a2a2a），与浅色主题冲突 | 主题重构时 Background 组件色值未同步 | ✅ 已修复：`#cbd5e1` |
| F4 | P2 体验 | fitView 初始过度放大，单节点占满屏幕 | 未限制缩放上限 | ✅ 已修复：`fitViewOptions={{padding:0.2,maxZoom:1}}` + `maxZoom=1.5` |
| F5 | P3 观察 | 自动化工具向标题输入框输入时文本追加而非替换 | 自动化工具 `type` 行为（非应用缺陷），但提示真实用户测试中需观察「输入框预填内容的选中/替换」交互 | 记录为真实用户测试观察点 |
| F6 | **P1 严重** | F2 同类缺陷普查（2026-07-26 补充）：13 个长耗时端点（character/storyboard/video/voice/subtitle/compose/quality/lipSync/postprocess 等）仍使用裸 `fetch` 无超时保护；`pollVideoTask` 在组件内 `while(true)` 无限轮询且无单次请求超时 | F2 修复时仅覆盖 `generateScript` 单点，未做同类普查；轮询逻辑违反 API 分层规范 | ✅ 已修复：新增 `API_TIMEOUTS` 15 档分级超时常量，13 个端点全部接入 `fetchWithTimeout`；`pollVideoTask` 移入 `api/client.ts`，单次请求 30s 超时 + 整体截止期限（默认 600s）超限抛「轮询超时」。新增 client.test.ts 19 条用例防回归，36/36 passed |
| F7 | P2 债 | 同一普查中发现 App.test.tsx 3 条用例因 UI 重构过期（顶栏标题、流程按钮收纳进下拉、「生成剧本」改名「新建剧本」） | UI 重构（P5）后测试未同步更新 | ✅ 已修复：测试改配新交互（fireEvent 展开下拉后断言），36/36 passed |

## 四、优化建议（按优先级）

| 优先级 | 建议 | 依据 |
|---|---|---|
| **P0** | 长任务分段进度提示：剧本/视频等分钟级生成展示阶段进度（如「大纲 → 分场 → 台词」）+ 已耗时间，替代单一 spinner | T2 观测：分钟级等待仅有 spinner 是最大焦虑源；后端已有 SSE 进度能力（`/progress`），前端可复用 |
| P1 | 首次使用引导：节点详情面板、提示词编辑入口可发现性弱，建议首次生成后一次性高亮提示「点击节点查看详情」 | T6 行为分析：详情入口依赖用户主动点击节点，无引导 |
| P1 | 全局 loading 期间明确锁定反馈：生成中禁用其他生成按钮已有，建议状态栏补充「当前正在生成：剧本」明示锁因 | F2 衍生：长任务中用户可能困惑为何其他按钮不可点 |
| P2 | 输入框体验：题材 datalist 预填项较多（19 个），建议真实用户测试验证「自由输入 vs 预设选择」的使用比例 | F5 观察点延伸 |
| P2 | 移动端任务路径单独验证：响应式断点（768/1024）已实现，但本轮未覆盖移动视口下的画布拖拽/菜单操作 | 响应式设计已实现，行为验证待补 |

### 5.1 目标用户画像与招募配额

| 画像 | 描述 | 配额 | 招募渠道 |
|---|---|---|---|
| **U1 AI 内容创作者** | 有 AI 绘画/视频工具经验（ComfyUI/即梦/可灵），想批量产出短剧内容 | 4 人 | AI 创作社群、Discord/QQ 群 |

- 总样本 **10 人**（可用性测试 5-8 人可发现 ~85% 问题，10 人留余量）
- 筛选问卷要点：近 3 个月是否创作过视频内容 / 是否使用过 AI 生成工具 / 职业背景
- 激励：按本地惯例提供 60-90 分钟测试酬劳或等值礼品

### 5.2 测试环境与设备

- 与本轮相同部署（前端 3501 + 后端 8100 + 集群服务在线），测试前用健康检查脚本确认 LLM/xDiT/HunyuanImage/LatentSync/video-enhance 全部可达
- 被试设备：1080p+ 显示器桌面 Chrome；记录工具：OBS 录屏（屏幕+鼠标轨迹）+ 可选鼠标点击热力记录
- 协议：think-aloud（边操作边说想法），测试员仅在「卡住 >2 分钟」时介入

### 5.3 关键任务路径（覆盖主要功能模块）

| 编号 | 任务 | 覆盖模块 | 成功标准 |
|---|---|---|---|
| R1 | 打开应用，描述「你认为这个页面能做什么」 | 首屏可理解性 | 能说出「生成短剧/视频」相关意图 |
| R2 | 输入一句话创意并生成剧本 | 创意输入 + 剧本 Agent | 剧本节点出现且内容可读 |
| R3 | 修改剧本标题并保存 | 模态框编辑 | 画布标题同步 |
| R4 | 生成角色定妆照，并尝试编辑提示词重新生成 | 角色 Agent + 提示词编辑 | 角色图出现；能找到编辑入口 |
| R5 | 生成一个分镜，再生成对应视频 | 分镜 + 视频 Agent | 分镜图/视频出现在节点上 |
| R6 | 为场景生成配音与字幕 | 配音 + 字幕 Agent | 音频可播放、字幕预览可见 |
| R7 | 合成成片并查看质检报告 | 剪辑 + 质检 Agent | 成片可播放，质检摘要可见 |
| R8 | 点击任一节点修改一项参数并保存 | 节点详情面板 | 保存后数据同步 |
| R9 | 在画布上缩放、拖拽、回到全景 | 画布交互 | 不迷失，能找回全部节点 |
| R10 |（U3 可选）执行唇形同步 + 后处理 | P4 高级能力 | 同步视频/4K 成片产出 |

### 5.4 采集指标与分析框架

**定量（每任务记录）：**
- 任务完成率（独立完成/提示后完成/失败）— 目标 ≥90%
- 完成时间（从任务宣读到成功标准达成）— 对比本轮基线（纯交互 ≤30s）
- 错误率（误点击次数 / 总点击数）— 目标 ≤5%
- 首次点击正确率（任务开始后第一次点击是否走在正确路径上）— 衡量可发现性
- 迷失度（画布任务中 fit view 被主动使用的频次）

**定性：**
- 任务后单题：SEQ（Single Ease Question，1-7 分）
- 全部任务后：SUS 可用性量表（10 题，目标 ≥70）+ 5 分钟半结构访谈（最困惑点 / 最惊喜点 / 缺什么）
- 录屏复盘：点击热区、犹豫点（鼠标悬停 >3s 无动作）、回退路径

### 5.5 执行流程（每人约 75 分钟）

1. 开场说明 + 知情同意（5min）
2. 背景问卷（5min）
3. R1-R9 任务执行 + think-aloud（45-55min，长生成等待期间穿插访谈）
4. SUS + 访谈（10min）

- 《问题清单》：按严重度 P0-P3 分级，关联录屏时间码证据

## 六、结论

模拟用户点击测试 5 条关键任务路径 **100% 通过、0 操作错误**，验证了从创意输入到节点编辑的核心链路在真实浏览器环境中可走通；过程中发现并修复 **1 个 P0 阻断缺陷（连接边缺失）** 与 **1 个 P1 严重缺陷（生成无超时）**。当前版本已具备进入真实用户招募测试的条件，按第五章方案执行即可。
