# AI 短剧工作台 — 系统性推进方案

## Context

M1-M3 已交付（剧本/角色/分镜/视频/配音/字幕 6 个 Agent），但规格书定义的 7 Agent 管线还缺剪辑和质检两个环节。同时项目存在质量缺口：零测试、文档过时、无进度反馈、无错误恢复。用户要求系统性推进，补全功能模块、添加测试、修复缺陷、优化体验、完善文档。

本次会话新增约束：先处理 MCP/GLM-5.2 兼容性问题，但不修改项目代码，仅给出排查清单；然后按原计划继续推进 P0-P7。

## 现状

- **已完成**：6 Agent（1677 行后端 + 1401 行前端），全链路实测通过
- **缺失**：剪辑 Agent（FFmpeg 可用）、质检 Agent（Qwen3-VL 未部署，可用 GLM-5.2 文本质检替代）
- **质量缺口**：零测试、README 停留在 M1、无进度反馈、无重试机制
- **MCP 兼容性**：项目自身代码中未使用 MCP 或 function calling（扫描结果仅有 `huggingface_hub` 第三方依赖含 `_mcp_client.py`），问题大概率在 Trae IDE 的 MCP server 配置层或外部系统，不在本仓库业务代码范围内

## 分阶段实施计划

### P-1：MCP/GLM-5.2 兼容性诊断（0.5 天，不修改项目代码）

**目标**：定位 `Invalid tool: non-support parallel function call` / `argument schema 与 GLM-5.2 不兼容` 的根因，给出可操作的排查清单。

**范围**：仅做只读检查和配置审计，不新增/修改 AICG-DownLoader 项目代码。

**排查清单**：

1. **确认报错发生位置**
   - 检查 Trae IDE 的输出面板 / 开发者工具（Help → Toggle Developer Tools）中完整错误堆栈
   - 区分是：Trae 调用 MCP server 时出错 / 你自己的后端服务调用 LLM tools 时出错 / HuggingFace hub 内部报错

2. **检查 MCP server 配置**
   - 打开 `~/.trae-cn/mcps/s_AICG-DownLoader-main-e55dee2e/solo_agent/<server>/SERVER_METADATA.json`
   - 检查 `mcpVersion`、`capabilities.tools`、`tools` 列表与当前 Trae 版本是否兼容
   - 检查每个 `tools/*.json` 的 `arguments` 是否使用标准 JSON Schema draft-07（本地 descriptor 已确认均为标准格式）

3. **关闭并行工具调用（最可能原因）**
   - GLM-5.2 通过 EXO 暴露的 OpenAI 兼容接口可能不支持 `parallel_tool_calls`
   - 在调用处显式设置 `parallel_tool_calls=False` 或 `tool_choice="auto"` 而非 `"required"`
   - 如果是 Trae 内部配置，尝试在模型设置中关闭 "Parallel Function Calling" 或 "Multi-tool"

4. **简化工具参数 schema**
   - GLM-5.2 对复杂嵌套 schema、 `anyOf` / `oneOf` / `additionalProperties` 支持可能不完整
   - 将所有 tool parameters 改为扁平对象，类型仅保留 `string` / `integer` / `boolean` / `array`
   - 移除 `default` 值、复杂 `enum`、嵌套 `$defs`

5. **验证 LLM 接口能力**
   - 直接 curl 测试 EXO 的 `/v1/chat/completions`：
     ```bash
     curl http://100.64.201.37:52415/v1/chat/completions \
       -H "Content-Type: application/json" \
       -d '{
         "model": "mlx-community/GLM-5.2-fp8",
         "messages": [{"role":"user","content":"hi"}],
         "tools": [{"type":"function","function":{"name":"echo","description":"...","parameters":{"type":"object","properties":{"msg":{"type":"string"}},"required":["msg"]}}}],
         "tool_choice": "auto",
         "parallel_tool_calls": false
       }'
     ```
   - 逐步开启 `tools`、`tool_choice`、`parallel_tool_calls`，定位哪个字段触发报错

6. **临时规避方案**
   - 如果模型不支持 tools，改为纯文本 prompt + 手动 JSON 解析
   - 使用 `response_format={"type":"json_object"}` 强制模型输出结构化 JSON，再在后端校验参数

**交付物**：`docs/MCP_COMPATIBILITY_TROUBLESHOOTING.md`（排查清单 + curl 测试脚本 + 规避方案示例）
**验收**：用户能根据清单定位到具体报错原因并应用临时规避方案。

## 技术决策

| 决策 | 选择 | 理由 |
|------|------|------|
| MCP 问题处理 | 只读诊断 + 排查清单，不修改项目代码 | 项目业务代码中未使用 MCP，问题在 IDE/外部系统层 |
| 进度反馈 | SSE | 单向推送，FastAPI 原生支持，EventSource 自动重连 |
| 质检 Agent | GLM-5.2 文本质检（P4a）+ Qwen3-VL-235B 视觉质检（P4b） | Qwen3-VL-235B-A22B-Thinking 是 2026 开源视频理解 SOTA，FP8 235GB 可部署于 Mac 集群 |
| 前端状态 | zustand | 依赖已声明，14 个 useState 需要重构 |
| FFmpeg 调用 | asyncio.create_subprocess_exec | 避免阻塞事件循环 |
| 测试 Mock | Monkey-patch BaseAgent 方法 | 不依赖外部服务，CI 可直接运行 |
